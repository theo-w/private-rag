# 长调用用进度通知表达进度，不改成流式生成

MCP 这一侧的 `ask` 一次要十几秒（检索加生成），改动前 stdout 在这期间完全没动静：客户端能看到的只有
「这次调用慢」，不知道是在检索还是在生成，也不知道有没有卡死。我们决定按 MCP 协议自带的**进度通知**
来表达进度——客户端在请求的 `params._meta.progressToken` 里放一个不透明标记，服务端在这次调用完成之前
写几条 `notifications/progress`，最后照常发一条响应——而**不**把 `ask` 改成流式生成。

通知只带「在做什么」和步数，不编造百分比：第几步是确定的，剩下多久不是。步数由工具自己声明
（`McpTool.progress_steps`：`kb_search` / `sql_query` 为 2，`ask` 为 3），服务端拿它当通知里的 `total`，
并在发响应之前补最后一条（成功「已完成」、工具层失败「已结束」）。通知与响应共用 `serve_stdio` 那一条
写路径，所以顺序天然是「通知都在响应之前」，不需要线程。

`ask` 的答案仍走 `engine.answer()`——与 HTTP `/chat` 完全同一条生成路、同一份采样参数。为了让「检索完成」
这个时刻能被报出来，`RagEngine.answer()` 多了一个可选参数 `on_retrieved`，在检索完成、开始生成之前调一次
并给出块数；不传时生成路径逐字不变。

## Considered Options

- **按阶段发进度通知**（选定）：协议里唯一能表达「这次调用还在进行」的机制，改动只落在对外通道。代价是
  客户端不带 `progressToken` 时什么也收不到（协议就是这么规定的：没带 token 就不许发通知），以及多了一条
  崩溃面——`serve_stdio` 只把 `json.loads` 包在 try 里，`handle` 冒出去的任何异常都会让整个 stdio 进程退出，
  所以取 token 全程只做类型判断、不兜异常。
- **把 `ask` 改成 `engine.stream()`**：能边生成边返回，但会给对外通道多出第二条生成路，答案与 HTTP `/chat`
  可能逐字不同（两条路的调用形状与采样参数各自演进），而 README 与 ADR 0004 的既有原则是「MCP 与 CLI / HTTP
  复用同一条链路」。协议里也没有「分段的工具结果」可以承接这些 token——`stream()` 的事件流在 MCP 侧只能
  攒回一个完整结果，等于多付一条生成路换不回任何东西。用户已拍板不这么做。
- **把 `answer()` 拆成「先检索、再生成」两处调用**，工具层自己报两个阶段：省掉 `on_retrieved`，但等于把
  `answer()` 的组合抄第二遍，检索与生成的搭配从此有两处定义，日后改一处漏一处。
- **用线程发「已等 X 秒」心跳**：客户端能看到时间在走，但两个写入者会交错 stdout，客户端可能读到半条消息。
  进度通知的内容（「正在检索」→「正在生成答案」）已经把「时间花在哪儿」说清楚了，不需要心跳。
- **声明一个 progress 能力字段**：2025-06-18 版协议里 `ClientCapabilities` 与 `ServerCapabilities` 都没有
  `progress` 字段，开关就是请求里的 token 本身。所以 `initialize` 一个字段都不加，客户端没声明任何能力
  也允许发通知。

## Consequences

- **没带 token 就一个字都不加**。响应必须与改动前逐字相同，这靠两层钉：单测比对带/不带 token 的响应，
  `serve_mcp.py --list-tools` 与 `origin/main` 的输出 `diff` 为空。客户端把 `_meta` 乱填（写成字符串、
  列表，或 token 写成 `true`——Python 里 `bool` 是 `int` 的子类，不能当成 `1`）一律按「没带」处理，
  并且不能让服务退出。
- **不发假消息**。参数校验没过、工具没注册、检索还没开始，都不发「正在检索」；工具体内失败补「已结束」
  而不是「已完成」，客户端不会停在半截。通知只在「客户端带合法 token」+「有人接通知」+「开关没关」三个
  条件同时成立时才挂回调，否则连关键字参数都不传——旧签名的工具类因此照旧可用。
- **`RAG_DISABLE_MCP_PROGRESS=1` 逐字退回今天的一问一答**（一条通知都不发）。开关从消费方模块属性读，
  与 v8.14 的 `CITATION_LOCATOR` 同一套做法，方便同进程对照。
- **ROADMAP 的「分段的工具结果」这条仍然开着**：协议里没有这种东西，工具结果只能一次性返回。真要边生成
  边返回得换通道（本机 HTTP 已有 `/chat/stream` SSE），不在 MCP 这一侧。ADR 0004 里「没有进度通知与流式
  工具结果」那条 Consequences 已按此改写。
- **扰动只落在对外通道**：评估链路不经过 MCP 工具，HTTP 与 agentic 两条链路都不读这些新参数，所以没跑
  评估 A/B。要证的只是「不传新参数时逐字不变」，由单测、`--list-tools` diff 与真机 stdio diff 钉住；
  冒烟里生成正文有 2 个字不同，用假引擎比对送进 `generate_answer` 的入参指纹全等，判为模型侧翻动，
  按既有噪声底口径措辞不算证据。
